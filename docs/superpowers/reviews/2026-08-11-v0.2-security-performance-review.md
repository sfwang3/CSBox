## Confirmed findings

### Important 1 — Check 缓存与大文本边界可产生 secret 假绿

- 接口：`src/csbox/check/detectors.py::FileInventory.text`、`src/csbox/check/rules.py::HardCodedSecretRule`、`src/csbox/pack/service.py`。
- 风险：文本缓存预算耗尽时返回 `None`，超过 256 KiB 的文本被轻量规则跳过，固定 512-byte overlap 可被长空白跨 chunk 绕过，以及小型 NUL/invalid-UTF-8 文件被当成非文本，都会让明显硬编码 secret 显示为 PASS；Pack 会继承该假绿。
- 复现：先用安全文件占满小缓存再放入 sentinel；把 sentinel 放在 256 KiB 之后；用 600 个空格把 `token =` 分隔到 1 MiB chunk 两侧；或在 ASCII assignment 前放置 NUL/invalid UTF-8 byte。
- 原覆盖：覆盖缓存命中和大文件跳过统计，但没有验证安全规则与 Pack 的最终语义。
- 修复：预算只限制保留内存，不限制扫描覆盖；所有未解码/大文件继续用固定块扫描；跨 chunk 的 horizontal whitespace 以有界状态归一化，不依赖固定 overlap；finding 不包含匹配内容。
- RED/回归：`test_check_scans_uncached_text_after_the_cache_budget_is_exhausted`、`test_check_and_pack_stream_scan_secrets_beyond_the_text_cache_limit`、`test_check_and_pack_stream_scan_secret_assignment_across_chunk_boundary`、`test_check_and_pack_scan_ascii_secrets_in_non_text_files`。
- 修复提交：初修 `03a12daf1dbed004250d7babfa039ca5853c093d`；边界 follow-up 为 `b3604d247b03079aaea415e7b173e506806642c1`。

### Important 3 — 多个输入/sidecar 仍使用无界或可跟随特殊文件的读取

- 接口：API scenario/OpenAPI/run repository、Lab metadata/captures/checkpoint/asciicast、config、export manifest。

- 复现：FIFO、symlink parent、实际触发 parser recursion 的 10,000 层 JSON/TOML、80 层受支持 OpenAPI、YAML alias、超限 sidecar；深层 API JSON response 可持久化但 Evidence collector/Markdown 原会递归失败。

### Important 4 — 发布流程存在 check-then-replace/no-replace 不一致

- 接口：Lab export、API evidence export、OpenAPI template publication、shared `safe_rename`。
- 风险：目标在 preflight 后出现时，普通 rename 可覆盖并发创建的用户数据；旧 destination 移到 backup 后出现的并发文件会被 rollback 覆盖；多文件发布的第二项失败时会留下新旧混合 canonical 集，破坏 manifest/Markdown/PNG/template 一致性。
- 复现：在 publish callback 中创建同名文件/目录；在 backup 后占据 destination；或让第一项 publish 成功、第二项抛出磁盘/权限错误。
- 原覆盖：覆盖静态 symlink/force 和部分 rollback，但没有并发出现目标及 Windows restoration 语义。
- 修复：默认发布使用原子 no-replace；Linux 使用 `renameat2(RENAME_NOREPLACE)`，普通文件有 hard-link fallback，Windows 使用原生 no-replace rename。rollback 始终 no-replace：若 canonical 被占据，先把占据者原子移到 `.csbox-recovery-*.bak`，再恢复完整旧 canonical 集；二次竞争时两份内容均保留，不 check-then-delete/replace 未证明所有权的数据。
- RED/回归：`test_template_publish_does_not_replace_a_destination_created_after_preflight`、`test_new_lab_export_does_not_replace_a_directory_created_during_publication`，API/Lab/OpenAPI 的 `rollback_preserves_a_concurrent_destination...` 与 `restores_the_old_set_when_a_later_publish_fails` 六条回归，以及 `tests/test_safe_paths.py` 的 no-replace/Windows fallback tests。
- 修复提交：初修 `03a12daf1dbed004250d7babfa039ca5853c093d`；事务 rollback follow-up 为 `b3604d247b03079aaea415e7b173e506806642c1`。

### Important 6 — Pack 路径与 archive verification 存在跨平台/复杂度问题

### Important 7 — Renderer、ConPTY 与 Replay 存在无界保留或重复大对象工作

- 接口：API/Lab PNG renderer、Windows ConPTY reader、Replay seek/checkpoint store。
- 风险：响应行数驱动无界像素分配、font cache 无界增长、ConPTY reader 的 bytearray backlog 无界；Replay 每次线性找 checkpoint并复制 event tail，cast fingerprint 整体读入；自产 checkpoint 超过读取上限后会反复重建。
- 复现：大 API body、超大 cell geometry、多样文本、持续 ConPTY 输出、100k events、把 checkpoint read budget 缩到 16 KiB。
- 原覆盖：结果正确性与 100k event 上界有覆盖，未断言像素/cache/backlog/读取次数及自产物与读取预算的一致性。

### Important 8 — API persistence 与 Evidence export 大响应上限不一致

## Performance/resource evidence

采用稳定的 call/object/byte 断言，不以 wall-clock threshold 作为唯一证据：

- Check 10,000 files：根目录一次 `scandir`；inventory 复用；cache bytes 有界；缓存预算不减少安全扫描覆盖。
- Check large secret：sentinel 位于 256 KiB 后仍被流式发现；不整体缓存大文件。
- Check hostile content：跨 1 MiB chunk 的 600-byte whitespace assignment、NUL/invalid UTF-8 包装中的 ASCII sentinel 均被发现并阻止 Pack。
- Pack 500 names：prefix comparison 不超过 `4N`；ZIP entry 以 1 MiB chunk 单次验证。
- Replay 100,001 events：checkpoint 数保持设计上限；seek 使用二分索引且不复制 tail tuple；持久化 document 不超过自身 read budget。
- API renderer：任何 `Image.new` 的像素数不超过 16,000,000；超宽在分配前拒绝；1 MiB 单行的 category/cluster 工作量为 `O(maximum_lines × width_cells)`，不会先遍历完整 body。
- API export：三个 11 MiB response 的合法 persisted run 可导出 64–144 MiB Evidence JSON；manifest 读取仍为 4 MiB。
- Lab renderer：病理 geometry 在 `Image.new` 前拒绝；正常 CJK long-component export 仍通过。
- ConPTY fake：未消费 backlog 不超过 1 MiB，读取后完整恢复 UTF-8 bytes，close 会唤醒 backpressure reader。

## Residual risk / known limits

- 非 POSIX 平台没有 directory-fd pin 能力；fallback 使用 reparse/static metadata 检查、原子 rename/no-replace，无法声称消除所有同用户并发换目录竞态。
- Windows ConPTY/native PowerShell 仅能在 Windows CI 作最终平台验证。
- 本地无 zsh。
- PNG renderer 依赖系统 CJK 字体，不捆绑大型字体。
- gitleaks 缺失时明确 SKIP；轻量 Check 不能替代组织级 secret/依赖安全扫描。
- 极大 checkpoint 会按 32 MiB 派生索引预算抽稀；回放正确性不变，但跨进程 late seek 可能比完整 5s/500-event 索引多回放一段尾部。
