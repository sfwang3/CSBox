# CSBox v0.3 Lab Session Correctness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Lab lifecycle, recording boundaries, ordered Capture transactions, and Review state semantics reliable for Batch 1.

**Architecture:** Keep `TerminalProxy` as the sole ordered terminal event pipeline: child output is emitted once, applied to the emulator, and dispatched to recorder and future result sinks in registration order. Move lifecycle ownership to `LabService`/`SessionRepository`, use explicit metadata diagnostics and stale recovery, and expose replay diagnostics to a state-aware Review controller without adding a new Lab TUI.

**Tech Stack:** Python 3.11+, Pydantic 2, pytest, Textual, pyte, asciicast v3, existing Unix PTY and Windows ConPTY backend interfaces.

## Global Constraints

- Preserve local/public Git history isolation; do not pull, merge, rebase, push, or force-push.
- Do not add raw keyboard input recording or Batch 2 Windows Terminal/ConPTY behavior.
- Use display-cell semantics for all Review text and preserve CJK/Unicode paths.
- Child non-zero exit is `completed` with `exit_code`; infrastructure failure is `failed`; interruption is `interrupted`.
- Capture-local failure must not terminate a healthy session or increment Capture count.
- Reference material stays outside CSBox and is never committed.
