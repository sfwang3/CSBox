# CSBox v0.3 Dedicated Windows Lab Host Candidate Implementation Plan

> **For agentic workers:** Execute this plan task by task, keeping each red/green test cycle focused.

**Goal:** Implement the approved Windows-only dedicated Lab host candidate: a deterministic fresh Windows Terminal surface, a separate bounded launcher/host READY handshake, and the existing ConPTY/recorder/input core running without the Windows alternate-screen surface.

**Architecture:** `csbox lab start` reserves a private launch intent and starts `wt.exe --window new` with a hidden host command. The host claims the intent exactly once, creates the real Lab session, and reports READY only after the child ConPTY and recorder are initialized. The host owns the only terminal-body writer: child VT output. Capture and state remain input-owner and OSC/out-of-band responsibilities. Unix direct Lab keeps its existing surface path.

**Tech Stack:** Python 3.11+, Typer, pywinpty/ConPTY on Windows, pytest, existing CSBox repository/session/recorder abstractions.

## Global Constraints

- Do not change Unix Lab surface behavior in this candidate.
- Do not emit body headers, status, debug text, cursor movement, clear sequences, or alternate-screen sequences from the dedicated Windows host.
- Keep `CreatePseudoConsole` flags at `0`; do not add a CPR parser, cursor model, or custom scrollback.
- Keep one Windows input owner; consumed F12/Ctrl-Space must not reach the child and ordinary/response-like input must remain forwardable.
- Preserve real child exit status, session recording/review compatibility, Capture feedback/count, resize, verbose exception chains, and stale recovery.
- Do not claim Windows Terminal manual, PS5.1, CPR, or final Batch 2 gates from Linux tests or Native CI.

### 2. Implement the private launch-intent store and Windows launcher

Prefer `wt.exe --window new new-tab ...` with a fresh working directory/surface and a hidden module host command. Classify WT launch failure, host startup failure, shell startup failure, timeout, and runtime state separately.

### 3. Add the dedicated host entrypoint and service integration

In dedicated mode, make the existing `TerminalProxy` use no surface. Mark READY after the existing repository owner is running and ConPTY/input/recorder initialization has completed. Keep the existing status presenter on OSC title/out-of-band state only.
