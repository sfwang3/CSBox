# CSBox v0.2 productization design

> 状态：已基于 `11a4879fb4d4362f5021f8cc34af6fc649efd9b5` 完成设计自审，按用户授权直接进入实施。

## 目标

CSBox v0.2 Alpha 面向计算机专业学生，把 API 实验变成可复核的报告证据链：

```text
TOML 场景 → HTTP 执行 → 断言 → 自动脱敏 → 运行记录 → PNG/Markdown/JSON → Review/交付
```

本轮同时把现有的 Lab Evidence、Project Check、Safe Pack 做成可持续使用的四条主链路，并保持本地优先、无账号、无云同步、无 telemetry。

不在范围内：AI 报告或结论、LLM API、插件市场、动态脚本、Web UI、云端服务、数据库服务器、账号系统、GraphQL、WebSocket、gRPC、自动上传用户数据和 Postman clone。

## 现状与约束

- 当前 usable-core 已包含跨平台 PTY/ConPTY、asciicast v3、Capture/Replay、Lab Evidence、真实 Home、Check、Safe Pack 和 CI；不重新实现这些能力。
- `src/csbox/api/` 只有 registry 占位；`pyproject.toml` 版本为 `0.1.0`，CLI 也没有 API 命令。
- Check 已建立一次 `FileInventory`，但文本规则通过 `text_files()` 重复读取文件；Pack 已安全 staging 和 ZIP 校验，但没有 dry-run、manifest 或确定性时间策略。
- 现有 renderer 的终端截图模型不适合 API 卡片；API renderer 只复用字体解析、display-cell 和安全输出的基础能力，不把 Terminal Renderer 改成通用 UI。
- Python 最低版本保持 `>=3.11`，CI 继续覆盖 3.11/3.14 与 Ubuntu/Windows。
- 所有正式 UI 不使用 Emoji；显示宽度统一使用 `wcwidth`/display-cell 语义。

## 方案选择

### 方案 A：领域核心 + 端口适配器（采用）

新增独立的 API domain、scenario parser、transport protocol、runner、repository、evidence renderer 和 Textual adapter。Service 只能依赖 `ApiTransport`，Evidence 只能接收已脱敏 `ApiEvidence`。优点是安全边界清晰、HTTPX 可替换、领域层不依赖 Textual，且每个任务可以独立测试。代价是新增文件较多，但这些文件与责任一一对应。

### 方案 B：把 API 直接并入现有 Lab/Exporter

复用现有导出流程和 TUI，但会把终端快照、HTTP 响应、不同的错误模型和不同的布局强行揉在一起；脱敏边界容易被 Lab 的原始数据路径绕过，后续维护风险高。不采用。

### 方案 C：通用插件/脚本执行框架

用可扩展脚本和插件处理 OpenAPI、断言与导出，短期看似灵活，但会引入 arbitrary code execution、版本兼容和供应链边界，违反本轮禁止动态脚本且超出课程工具目标。不采用。

## API 领域模型

`src/csbox/api/` 的领域层使用 Pydantic/dataclass 和标准库，不导入 Textual、Typer 或 Rich。核心模型如下：

- `ApiRequest`：method、URL、query、headers、JSON/form/multipart body、Bearer token、timeout、redirect policy、TLS verify。
- `ApiResponse`：status、headers、body text、elapsed、content type、response size；原始值只在一次运行内存中存在。
- `ApiScenario`：场景元数据、变量和有序 `ApiStep`。
- `ApiStep`：名称、请求、断言列表；运行默认继续后续 step。
- `ApiAssertion`：status、status range、header exists/equal、JSON path exists/equals/type、body contains/not-contains。
- `ApiAssertionResult`：`PASS`/`FAIL`/`SKIP`、预期、实际、位置和安全的说明。
- `ApiRun`：run id、scenario、时间、耗时、版本、step 结果和最终状态。
- `ApiRunResult`：运行层面的 assertion/runtime/config 状态与汇总。
- `ApiEvidence`：每一个 step 的已脱敏请求、响应、断言结果和可渲染文本；它不保存 raw request/raw response。

状态和退出码固定为：

| 语义 | 领域状态 | CLI 退出码 |
| --- | --- | ---: |
| 全部断言通过 | PASS | 0 |
| 至少一个断言失败，且无 runtime error | FAIL | 1 |
| TOML/OpenAPI/变量/参数错误 | CONFIG_ERROR | 2 |
| 网络、DNS、timeout、响应读取等 runtime error | RUNTIME_ERROR | 3 |

如果一次运行同时有 assertion fail 和 transport error，退出码使用 3；JSON 中保留每一步的具体状态。默认继续收集结果，`--fail-fast` 在第一个失败的 step（断言或运行错误）后停止。

## Scenario 文件与变量

场景文件使用 Python 3.11 自带 `tomllib` 解析的 TOML：

```text
.csbox/api/scenarios/*.toml
.csbox/api/runs/<run-id>/metadata.json
.csbox/api/runs/<run-id>/result.json
```

最小格式：

```toml
name = "用户登录"

[variables]
base_url = "http://127.0.0.1:8000"
email = "student@example.com"

[[steps]]
name = "登录成功"
method = "POST"
url = "{{base_url}}/api/auth/login"

[steps.json]
email = "{{email}}"
password = "{{PASSWORD}}"

[[steps.assertions]]
type = "status"
expected = 200

[[steps.assertions]]
type = "json_path"
path = "$.code"
expected = 200
```

支持 HTTP method：GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。body 只允许 JSON、form、multipart 三种声明方式；Bearer token 是 header 的安全便捷写法，不能与显式 Authorization header 产生歧义。

变量优先级从低到高为：项目配置 `[api.variables]`、环境变量、scenario `[variables]`、CLI `--var key=value`。环境变量按变量名精确读取，若不存在再读取 `CSBOX_VAR_<NAME>`；不会把整个环境写入运行记录。`{{name}}` 是唯一插值语法，不引入表达式、脚本、eval 或条件语言。未解析变量是 CONFIG_ERROR。OpenAPI 生成的 `{{TODO_xxx}}` 会保持为 placeholder，并在运行时给出可修复的配置错误。

## Transport 与错误边界

`ApiTransport` Protocol 只暴露 `send(ApiRequest) -> ApiResponse`。`HttpxTransport` 是唯一直接调用 HTTPX 的实现：

- 使用 connect/read/write/pool timeout 组装 `httpx.Timeout`；默认 follow redirects 为 false，TLS verify 为 true。
- 统一映射 invalid URL、DNS、连接失败、timeout、TLS、响应读取/解码错误为稳定的 `ApiTransportError`，用户主文案中文，`--verbose` 才显示技术 cause。
- 不使用 shell，不拼接命令；请求 URL、headers、body 在送出前只在内存构造。
- response body 有大小上限；超过上限截断为证据安全摘要，并保留 response size。

## Secret 与隐私模型

`RedactionPolicy` 维护大小写不敏感的 header/key 名集合，默认覆盖：Authorization、Proxy-Authorization、Cookie、Set-Cookie、password、passwd、token、access_token、refresh_token、jwt、secret、api_key、apikey、client_secret；用户可配置额外字段。

`Redactor` 同时处理 headers、URL credentials/query、JSON object/list、form/multipart 和任意文本。变量解析时收集非空敏感变量值，在最终文本中做 exact replacement，避免 secret 出现在普通字段、异常说明或 body 字符串中。规则是：

1. raw secret 只允许留在本次 HTTP 请求所需的内存对象中；
2. persistence、TUI、日志、PNG 文本模型、Markdown、JSON export 只接收 redacted view；
3. assertion 的实际值和 transport error 不直接格式化 raw response；
4. `Authorization: Bearer value` 输出为 `Authorization: Bearer ••••••••`，其他 secret 使用 `[REDACTED]`；
5. 测试用 sentinel secret 必须在所有证据、日志与 JSON 中完全不存在。

## Runner、Persistence 与 CLI

Runner 执行静态变量插值后的 step，按文件顺序执行，生成 `ApiRun` 和逐 step `ApiEvidence`。Repository 使用临时文件 + `os.replace` 写 metadata/result，run id 只允许单一安全 path component；写入内容只含 schema version 1 的稳定 JSON 字段和 redacted view。

CLI 入口：

```text
csbox api run <scenario.toml> [--var key=value] [--fail-fast] [--json|--plain] [--verbose]
csbox api list [--json|--plain]
csbox api import <openapi.json|openapi.yaml> [--output DIR] [--force]
csbox api export <run> [--output DIR] [--theme dark|light] [--force] [--json|--plain]
csbox api
```

`--json` 所有 machine-readable API 输出以 `schema_version: 1` 开头；`--plain` 使用中文 labels，方法、URL、HTTP status、JSON 等技术内容保留英文。默认用户错误按“发生了什么 / 在哪里 / 怎么处理”展示，不显示 traceback；`--verbose` 展示技术异常摘要。

## OpenAPI import

OpenAPI 3.x 的 JSON/YAML 只用于导入接口结构：读取 path、method、operationId、parameters、requestBody schema、response status，输出 TOML scenario template。没有默认值的 path/query/header/body 值全部变成 `{{TODO_name}}`，不自动编造账号、密码、学号、ID 或业务成功条件；生成的 assertions 默认为空，并在 step 描述中保留已声明 response status 供学生选择。

YAML 通过成熟的安全 loader 读取，禁止自定义 tags。非法版本、重复 operation、无法读取的 schema 都是清晰的 CONFIG_ERROR。

## API evidence 与视觉设计

API evidence 独立于终端截图，布局为报告卡片：

```text
┌ CSBox / 接口测试记录 ───────────────────────────┐
│ POST /api/auth/login                            │
│ 请求                                            │
│   Content-Type: application/json                │
│   { "password": "[REDACTED]" }                 │
│ 响应                                            │
│   HTTP 200   84 ms   application/json           │
│   { "code": 200, "message": "success" }      │
│ 断言                                            │
│   通过  Status = 200                            │
│   通过  $.code = 200                            │
└─────────────────────────────────────────────────┘
```

PNG、Markdown、JSON 都从同一个 immutable `ApiEvidence` 生成；PNG 使用共享 `FontResolver`，JSON/代码块按 display-cell 自动换行，覆盖 CJK 双宽、长 URL、中文 JSON、深层 JSON 和大响应摘要。dark/light 使用成对的语义 token：深蓝黑背景、近白正文、绿色 PASS/运行态、红色 FAIL、琥珀 WARN；颜色不单独承载状态。

TUI 延续深色系统工具风格：等宽字体、细边框、低动效、数据优先，不使用图表和装饰性统计。≥120 列是场景/step 列表 + request/response/assertion detail 双 pane；80–119 列为单主 pane，通过 Tab 切换；80×24 仍显示场景名、运行汇总、当前 step 和可用键。Home 只显示真实的最近实验、最近 API Run、check 状态和五个入口，不加入 fake chart、activity graph、productivity score 或 AI recommendation。

## Check、Pack 与版本工程

- Check：`FileInventory` 一次建立排序稳定的 file/directory/text index，文本只在上限内读取一次并在多规则间复用；二进制和大文件跳过全文读取并产生可解释的 warning。detector 补充 pnpm/yarn、uv/Poetry、Gradle Kotlin DSL 与多模块目录识别。`--deep` 仅在 PATH 存在 `gitleaks` 时用参数数组调用；缺失返回 SKIP 和中文安装提示，绝不把工具 stdout 当用户输出。
- Pack：增加无副作用 `plan/dry-run`，显示 included/excluded/rejected、文件数和字节估算；可选 manifest.json 写入 ZIP，内容只有 CSBox version、UTC pack time、project type、相对 included files 和 excluded summary，不含用户名、HOME、绝对路径或 secret。ZIP entries 稳定排序、POSIX 相对路径、固定 DOS timestamp/权限归一化，尽量实现 byte-identical；若平台压缩实现仍造成差异，文档化边界。
- 版本：`importlib.metadata` 是运行时单一来源，pyproject 推进到 `0.2.0` 后 `csbox --version`、session metadata、manifest 和 README 使用同一版本。准备 CHANGELOG，但不声称已发布 PyPI。
- 安装：CI 构建 sdist/wheel，并在临时 venv、隔离 `UV_TOOL_DIR`/`UV_TOOL_BIN_DIR` 下执行 wheel install 和 `uv tool install` smoke；pipx 若 runner 有命令则执行，否则明确未验证/skip。

## Reliability、安全与测试策略

重要逻辑遵循 RED → GREEN → REFACTOR：先写失败测试再实现。测试分为纯 domain、service/CLI、renderer/TUI、真实本地 HTTP server、PTY integration 和标记为 `stress` 的长压测。

- redaction、scenario parser、assertion、OpenAPI import、safe paths、pack manifest/reproducibility、recovery、schema 都有 sentinel/非法输入回归测试。
- display width property/fuzz-like 测试随机 ASCII/CJK/combining/full-width，保证 truncate 不超过 cell limit；scenario parser 的随机非法 TOML 只能产生可控错误。
- 录制器至少测试 100,000 event 的有限 benchmark，以及 12,000+ 字符、resize、Ctrl+C、shell exit、repeated capture；重型测试不进入默认几十分钟 CI。
- corruption 测试覆盖 truncated cast、invalid cast line、captures/checkpoint/metadata 损坏和 partial export；原始 cast 保留，派生 checkpoint 可重建，captures backup 可恢复，不做自动 destructive repair。
- TUI `run_test` 覆盖 80×24、100×30、120×35、160×45，以及 Home、Review、API、Check、Pack confirmation、Help、Error Modal 的 focus/Tab/Esc/Enter、长中文路径和 empty/error state。
- 安全审查重点覆盖 URL credentials、Authorization/Cookie/password、redirect/TLS、pack traversal/symlink/ZIP path、check binary、session cwd/env、subprocess shell injection；Critical/Important 必须有修复后的回归测试。

## 实施顺序与任务边界

每个任务都必须有自己的 RED/GREEN 测试、相关检查和逻辑 commit，顺序如下：

1. CI action/runtime、版本单一来源、JSON schema 基础。
2. API models/errors、redaction、variables、TOML scenario parser。
3. transport protocol/HTTPX、assertions、runner、CLI run。
4. persistence/list、OpenAPI import。
5. API evidence domain、PNG/Markdown/JSON export、secret audit。
6. API TUI 与 Home 真实入口、统一错误体验。
7. Check inventory/deep scan/detector 性能与大型 fixture。
8. Pack dry-run/manifest/deterministic ZIP。
9. Lab stress/recovery/property/TUI/平台回归。
10. wheel/tool install、docs、security/performance/architecture review、release gates、push。

## 验收标准

本轮只有在以下条件都真实执行后才可声称 v0.2.0 repository-ready：

- 本地最终 pytest、Ruff、format、lock、build 和 CLI help/doctor 全部有新鲜输出；
- 本地临时 HTTP server 完成 POST login、GET profile、错误 status、JSON/header assertion、timeout、redaction、persistence、PNG/Markdown/JSON 全链路；
- TemporaryDirectory 中的真实 sample project 完成 check/pack dry-run/verify，ZIP 不含敏感文件，仓库无生成物；
- Ubuntu/Windows CI workflow 保持 Python 3.11/3.14；Windows ConPTY smoke、Linux Bash/Zsh smoke 按环境实际报告，不能用 Ubuntu 冒充 WSL 或 GUI Terminal；
- 最终 `git diff --check`、`git ls-files`、状态和远端同步检查通过，禁止 force push、reset、历史重写；
- 任何未跑到的项目在最终报告中写“未验证”，不依据代码外观推断通过。
